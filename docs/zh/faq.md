# 常见问题

[English](../en/faq.md) | **中文** | [Русский](../ru/faq.md)

## RustVPN 是一套新的 VPN 协议吗？

不是。它是 GoVPN 5.7 的线兼容实现。Rust 客户端可与 Go 服务器配合，反之亦然。数据包格式、标志、配置与统计字段都相同。

## 为什么选择 Rust 而不是 Go？

目标是打造第二套独立实现，可与 Go 代码做差分测试，并能更精细地控制数据路径。Rust 提供可预测的内存使用、无垃圾回收停顿，并使热路径可以做到零分配。本项目明确**不**假定 Rust 天生更快；性能结论均针对同一机器上的 Go 构建进行测量（参见[性能](performance.md)）。

## 为什么不用 TLS？

- TLS 是一个庞大、复杂的协议，带有许多可选扩展。
- 经典 TLS 密码套件使用先认证后加密的顺序。
- 主流 TLS 栈极其庞大，相对于此处所需的小攻击面而言难以审阅。

RustVPN 需要的是一种固定、最小化的隧道格式，而非通用传输安全。

## 为什么不用 SSH？

- SSH 的早期协议版本同样使用先认证后加密。
- OpenSSH 不提供强零知识口令认证。

## 为什么不用 IPsec？

它缺乏强零知识口令认证，且其配置/代码面要大得多。

## 为什么用口令进行认证？

人类可以记住 100–200 字符的口令短语，这能提供较高的整体熵，同时无需硬件令牌或安全密钥存储。与密码不同，口令短语可以很长且依然便于记忆。这正是 RustVPN 采用 PAKE 和增强型验证器、而非预共享密钥的原因。

## 为什么所有网络配置都要手动进行？

要由一个工具正确配置的部署方式和协议实在太多。如同以太网线缆，VPN 是一层：地址、路由、MTU、NAT 等由管理员分配。这使守护进程保持小巧且可审计。

## 为什么不支持 Windows 或 macOS？

封闭的专有系统无法让你充分控制计算设备，难以满足以密码学为核心的安全需求。仅在 Linux 上测试；FreeBSD/macOS 支持可能通过 `tun` crate 工作（`GOVPN_IO_URING=0` 强制使用 epoll TAP 后端），但未经验证。

## 这里的完美前向保密是什么意思？

泄露长期机密（口令或验证器）不会解密先前截获的流量：每个会话都使用新鲜的 DH 值。PFS 是逐会话的；它无法挽回从活动内存中泄露的会话密钥。

## "客户端是匿名的"是什么意思？

观测网络的第三方无法区分一个客户端的流量或握手与另一个客户端的。身份不会以可被关联的方式明文发送。

## "抗审查"是什么意思？

应当无法将 RustVPN 流量与 `cat /dev/urandom | nc host` 区分开。如果观测者无法区分，那么唯一可行的政策就是封锁所有看起来随机的流量。

## 何时应使用无加密模式？

当某司法辖区可强制披露加密密钥或禁止加密函数，但不禁止认证/签名时。它仍通过编码提供机密性，代价是每个数据包多出 4128 字节，且在客户端需要 TCP。不要仅因名字听起来更安全就使用它——它是法律/合规工具，而非性能特性。参见[协议 → Encless](protocol.md#encless)。

## 何时应使用 noise？

当你关心隐藏数据包大小，或需与 CPR 配合时。若没有 noise（以及 CPR），观测者可像对待 TLS、SSH 或 IPsec 那样，从包长度和时序推断流量模式。单靠 noise 隐藏长度但不隐藏时序；CPR 隐藏时序。两者都消耗带宽。

## 何时应使用 timesync？

当你希望阻止主动 DPI 重放截获的首个握手包，以确认给定身份存在、且该服务器是 RustVPN 时。它要求两侧时钟合理同步。若不启用，服务器会响应被重放的首条消息，从而暴露其存在。

## 我能对守护进程发起 DoS 吗？

每个传输数据包都会在执行昂贵计算前先被认证，且实现会限制队列与握手状态的数量。首轮握手消息按来源 IP 限制为 **5/s**（突发 10），全局 **200/s**（突发 400）；超出部分会被丢弃，TCP 握手还需通过并发信号量。实践中 TCP/UDP 栈开销通常占主导。仍请尽可能对端口做防火墙限制。

## 为什么用 YAML？

YAML 支持注释、便于人类编辑，且其锚点/别名对于多个 peer 共享选项非常方便。XML 对人类不友好；JSON 缺少注释。

## RustVPN 和 GoVPN 可以并行运行吗？

可以。在同一主机上使用不同的端口与 TAP 设备/子网，或替换现有部署的一侧。参见[运维 → 共存](operations.md#coexistence-with-an-existing-govpn)。
