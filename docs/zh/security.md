# 安全

[English](../en/security.md) | **中文** | [Русский](../ru/security.md)

本页概述 RustVPN 能抵御什么、不能抵御什么，以及实践中至关重要的运维注意事项。

## 安全属性

- **基于共享口令的双向认证。** PAKE 握手在不发送口令的前提下证明对它的掌握，服务器则证明其持有匹配的验证器。主动攻击者若无口令猜测或突破原语，就无法冒充任意一方。
- **增强型、抗字典的验证器。** 服务器存储 Argon2d 派生的验证器加一个 Ed25519 公钥。窃取它并不能让攻击者以客户端身份通过认证，而 Argon2d 使离线猜测代价高昂。
- **完美前向保密。** 会话密钥由新鲜的 Diffie-Hellman 值派生。日后泄露长期口令或验证器，也无法揭示先前记录的会话。PFS 是逐会话的：它无法保护从活动内存中泄露的会话密钥。
- **认证传输。** 每个数据包在使用前都用一次性 Poly1305 密钥计算 MAC；篡改和伪造会被拒绝。这种 encrypt-then-MAC 式的构造避免了先认证后加密的陷阱。
- **重放保护。** 257 位滑动窗口拒绝重复及过旧的序列号；握手也携带新鲜 nonce。可选的 `timesync` 进一步收窄握手包的有效窗口。
- **客户端匿名性。** 第三方无法区分某一个客户端的握手/传输字节与另一个客户端的、或与随机数据的差异。
- **抗审查。** 握手与传输数据包被设计为与噪声无法区分；`noise` 隐藏包长度，CPR 隐藏时序。
- **无压缩。** 没有压缩层，因此压缩侧信道不适用。

## 注意事项

1. **使用长且高熵的口令。** 整体安全取决于口令强度。优先使用 100 字符以上的短语或随机高熵字符串。口令是唯一的人类机密。
2. **切勿在多个客户端之间复用一个口令/验证器。** 每个客户端都必须拥有自己的身份和验证器。共享验证器会破坏"一身份一对端"模型并削弱匿名性。
3. **口令只保存在客户端上**，放入仅服务用户可读的文件（例如 `0640 root:rustvpn`）。服务器只需要长格式验证器。不要把口令放进 `peers.yaml`、shell 历史记录或服务单元文件。
4. **像对待任何凭据一样保护身份/验证器文件**：限制权限，不要有全局可读的备份。
5. **使用可信的 RNG。** 默认使用操作系统 CSPRNG。若你平台的熵源可疑，请为每个消耗随机性的可执行文件（服务器、客户端、验证器）都提供 `-egd`。
6. **不要自创自定义模式。** 坚持使用文档化的组合；模式不匹配会表现为 `FramesUnauth` 增长，而不是安全的回退。

## 验证器泄露

若攻击者获取了服务器的 `peers.yaml`：

- 他们无法冒充客户端（验证器不含私钥）。
- 他们可以针对 Argon2d 验证器尝试离线字典攻击；请使用强口令以及默认（或更高）的 Argon2d 开销。
- 他们会得知身份和公钥；按设计身份本就不是机密。

若攻击者获取了客户端口令：

- 在验证器轮换之前，他们可以冒充那一个客户端。
- 立即轮换：生成新验证器并替换两侧（参见[运维 → 口令轮换](operations.md#passphrase-rotation)）。

## Encless 考量

无加密模式使用 AONT + Chaffing-and-Winnowing，即仅使用认证原语来保持机密性与真实性。它可抵御那些能强制获取加密密钥或禁止加密的司法辖区。它**不能**抵御能突破底层认证原语的攻击者，而且开销较大。数据包序列号默认仍由 XTEA 混淆；这种混淆用于流量随机化，而非机密性，且不影响前向保密。

## 已知缺口与运维风险

- **握手洪泛已受限。** 首轮握手消息按来源 IP 限制为 5/s（突发 10），全局 200/s（突发 400）；超出部分会被丢弃。TCP 握手还需通过并发信号量。请保持端口防火墙限制，并监控 `FramesUnauth`。
- **网络层的拒绝服务始终可能发生。** 守护进程在执行昂贵计算之前先认证传输数据包，并限制内部队列，但无法阻止链路饱和。
- **统计端点没有认证。** 将其绑定到 `127.0.0.1`（或隧道地址），绝不要对外公开。
- **管理端是高价值目标。** `rustvpn-admind` 可写 `peers.yaml`、查看客户端元数据并踢下线，但它**不持有 `CAP_NET_ADMIN`**，只通过本地控制 socket 操作数据面。默认只绑回环；远程访问应经 TLS 反代/VPN，并启用 `-cookie-secure`。管理端不提供脚本内容编辑/上传；server 侧 `-script-dir` 校验脚本路径与所有权，防止管理端被攻破后升级为任意脚本执行。详见 [`admin-web-ui.md`](../admin-web-ui.md)。
- **管理端 `/metrics` 与 `/healthz` 不鉴权。** 它们只应通过回环或受限网络访问；不要与管理端口一起直接暴露到公网。
- **没有自动 MTU 调整。** MTU 配置错误会导致大帧被拒绝；这不是机密性问题，但可能看起来像故障。
- **仅在 Linux 上测试。** 请在你能够审计和测试的平台上运行。

## 加固清单

- [ ] 专用非特权用户；`NoNewPrivileges=yes`。
- [ ] 边界集中仅有 `CAP_NET_ADMIN` 和 `CAP_NET_RAW`。
- [ ] `peers.yaml`、口令和环境变量文件为 `0640`，属主 `root:rustvpn`。
- [ ] up/down 脚本为 `0750`，且除必要外不可由服务用户写入。
- [ ] 统计仅绑定回环地址。
- [ ] 防火墙仅允许 VPN 端口，最好限制为已知客户端地址。
- [ ] 口令逐客户端唯一，并在有怀疑时轮换。
- [ ] 使用你自行编译或已验证的构建（`cargo build --release --locked`），并跟踪依赖审计（`cargo audit`、`cargo deny`）。
- [ ] `peers.yaml` 的备份按凭据保护。

## 报告问题

安全报告应以私密方式提交给维护者，而不是公开的问题跟踪器。请包含受影响的组件（crypto、protocol、net、client/server）、版本/提交，以及尽可能提供最小复现。
