# Протокол

[English](../en/protocol.md) | [中文](../zh/protocol.md) | **Русский**

RustVPN реализует проводной протокол GoVPN 5.7 байт в байт. Эта страница описывает составные части, необходимые для понимания конфигурации и свойств безопасности. Там, где старое руководство GoVPN и код расходились, приоритет отдаётся коду; реализация на Rust проверяется дифференциальным тестированием по векторам, сгенерированным кодом на Go.

## Криптографические примитивы

| Назначение | Алгоритм |
|---|---|
| Согласование ключей | X25519 поверх представителей `extra25519` / Elligator |
| Аутентификация | Ed25519 (выводится из верификатора Argon2d) |
| Хеш | BLAKE2b-256 |
| KDF парольной фразы | Argon2d v1.3, 32-байтный результат используется как seed для Ed25519 |
| Потоковый шифр | Salsa20 (8-байтный nonce) / XSalsa20 (24-байтный nonce) |
| MAC | Poly1305 |
| Последовательный PRP | XTEA |
| Кодирование (encless) | AONT + Chaffing-and-Winnowing |

## Идентичность и верификатор

Идентичность (identity) клиента — это 128-битное несекретное значение. Оно используется как ключ XTEA для `IDtag` в рукопожатии и как соль Argon2, а также появляется в выводе статистики. Его безопасно передавать и хранить в открытом виде; PRP, применяемый к нему в сообщениях рукопожатия, затрудняет DPI/деанонимизацию.

**Верификатор (verifier)** имеет вид:

```
$argon2d$m=<KiB>,t=<iterations>,p=<parallelism>$base64(id)[$base64(pubkey)]
```

- Короткая форма (клиент): только идентичность. Клиент выводит ключ Ed25519 из парольной фразы и идентичности.
- Длинная форма (сервер): идентичность + открытый ключ Ed25519. Сервер никогда не видит парольную фразу и не может выдать себя за клиента, даже если его файл утечёт.

Результат Argon2d (32 байта) используется напрямую как seed для Ed25519. Параметры по умолчанию — `m=4096`, `t=128`, `p=1`.

## Рукопожатие (PAKE DH A-EKE)

Сессию устанавливают четыре сообщения. Каждое сообщение заканчивается **IDtag**: первые 8 байт открытого текста, зашифрованные XTEA с идентичностью клиента в качестве ключа (и XOR с округлённой меткой времени, когда включён `timesync`). Сервер использует его, чтобы найти peer'а; он также помечает пакет как рукопожатие.

Подготовка:

1. У клиента есть идентичность, парольная фраза и открытый ключ верификатора сервера (`DSAPub`).
2. Он выводит `DSAPriv`/`DSAPub`, генерирует DH-пару ключей `CDHPub`/`CDHPriv` и 64-битный nonce `R`.
3. `El()` — это кодирование представителя Elligator; `enc(k, n, m)` — шифрование Salsa20/XSalsa20 с ключом `k` и nonce `n`.

```text
1. Client → Server   48 bytes
   R || enc(H(DSAPub), R, El(CDHPub)) || IDtag

2. Server → Client   80 bytes
   enc(H(DSAPub), R+1, El(SDHPub)) || enc(K, R, RS || SS) || IDtag

3. Client → Server  120 bytes
   enc(K, R+1, RS || RC || SC || Sign(DSAPriv, K)) || IDtag

4. Server → Client   16 bytes
   enc(K, R+2, RC) || IDtag
```

- Сервер узнаёт адрес клиента, декодирует `CDHPub`, генерирует `SDHPriv`/`SDHPub`, вычисляет `K = H(DH(SDHPriv, CDHPub))` и отправляет 64-битный `RS` вместе с 256-битным pre-master secret `SS`.
- Клиент вычисляет `K`, восстанавливает `SS`, генерирует `RC` и 256-битный `SC` и подписывает `K` своим ключом Ed25519.
- Сервер проверяет подпись открытым ключом из верификатора, сравнивает `RS` и выводит ключ сессии
  **`MasterKey = SS XOR SC`**.
- Клиент подтверждает `RC`; теперь обе стороны разделяют `MasterKey`.

`MasterKey` — 256-битный ключ с высокой энтропией. `K` выводится из DH и имеет запас стойкости не более 128 бит, поэтому используется только во время рукопожатия. Значения `R*` обеспечивают рандомизацию рукопожатия и двустороннюю аутентификацию.

При включённом **noise** сообщения рукопожатия дополняются до размера MTU. При включённом **encless** каждый вызов `enc()` заменяется на AONT + chaffing над дополненными данными.

## Транспорт

```text
PACKET = TAG || CIPHERTEXT || NONCE

NONCE      = XTEA(PRP_KEY, SERIAL)
CIPHERTEXT = Salsa20(KEY, NONCE, DATA || PAD(0x80) || ZEROS)
TAG        = Poly1305(AUTH_KEY, CIPHERTEXT || NONCE)
```

- `SERIAL` — номер последовательности пакета: нечётный для направления клиент→сервер, чётный для сервер→клиент, увеличивается на 2. Клиент и сервер начинают с 0 и 1 и ожидают соответственно 2 и 3.
- `PRP_KEY` — первые 128 бит keystream Salsa20 с ключом сессии и нулевым nonce. `SERIAL` внутри хранится в открытом виде, но передаётся только как зашифрованный XTEA `NONCE`.
- `ENCRYPT` использует установленный ключ сессии и зашифрованный serial в качестве nonce для Salsa20. Первые 32 байта keystream — это одноразовый ключ Poly1305, следующие 32 байта отбрасываются, а шифрование полезной нагрузки начинается с байта 64.
- `DATA` — это Ethernet-кадр. `PAD` — один байт `0x80`; за ним при необходимости следуют нулевые байты, чтобы заполнить пакет до MTU (noise/CPR).
- Повторные или слишком старые serial отбрасываются **скользящим 257-битным окном воспроизведения**.

## Noise

Noise дополняет каждый исходящий пакет до настроенного MTU. Он скрывает длины полезной нагрузки и необходим для нужного эффекта CPR; включайте его на обеих сторонах. По умолчанию он выключен и может заметно увеличить трафик. Стоимость полезной нагрузки см. в разделе [MTU](configuration.md#mtu).

## Encless

Режим без шифрования заменяет потоковое шифрование **кодированием**, сохраняющим конфиденциальность:

```text
PACKET  = ENCODED || NONCE
ENCODED = Chaff(AONT(DATA || PAD || ZEROS))
NONCE   = XTEA(PRP_KEY, SERIAL)
```

- AONT (All-Or-Nothing Transformation) — преобразование без ключа: для декодирования любой части требуется всё закодированное значение.
- Chaffing-and-Winnowing использует только Poly1305 (примитив аутентификации), чтобы кодировать биты как пары кандидатных MAC. Здесь нет ни функции шифрования, ни отдельного явного MAC.
- Каждый пакет вырастает на **4128 байт** (32-байтный заголовок AONT + 4096 байт chaff), поэтому этот режим дорог.
- Он принудительно включает noise. Клиент поддерживает его только по TCP, как и GoVPN; сервер должен прослушивать TCP (или `all`).

Зачем он нужен: в некоторых юрисдикциях можно принудить раскрыть ключи шифрования, но не ключи аутентификации/подписи, а в некоторых шифрование прямо запрещено. Encless сохраняет конфиденциальность, используя только примитивы подписи/MAC. Его название относится к механизмам, а не к результату: передаваемые данные по-прежнему конфиденциальны и аутентичны.

## Сетевой транспорт

UDP используется по умолчанию и рекомендуется: он легче и позволяет избежать патологии «TCP meltdown» (блокировки начала очереди при надёжном транспорте поверх надёжного). TCP существует для сред, где разрешён только TCP. `-proto all` на сервере прослушивает оба транспорта.

## HTTP-прокси

На проводе прокси — это просто TCP. Листенер `-proxy` на сервере отвечает `HTTP/1.0 200 OK` на любой запрос и входит в конечный автомат TCP-сессии; клиент отправляет `CONNECT host:port` и, при необходимости, `Proxy-Authorization`. Байты рукопожатия и транспорта идентичны прямому TCP-соединению.

## Замечания о совместимости

Следующее намеренно идентично GoVPN 5.7 и покрыто байт-точными векторами:

- размеры сообщений рукопожатия, порядок полей, позиция заполнения и `IDtag`;
- смещения Salsa20 (ключ аутентификации, отбрасываемые байты, начало полезной нагрузки);
- чётность serial, шаг, начальные/ожидаемые значения и порядок байтов XTEA;
- семантика окна воспроизведения;
- расширение encless и раскладка nonce XSalsa20;
- синтаксис строки верификатора, параметры Argon2d и вывод seed для Ed25519;
- переменные скриптов `GOVPN_IFACE` / `GOVPN_REMOTE` и имена полей JSON статистики.
