# Справочник по конфигурации

[English](../en/configuration.md) | [中文](../zh/configuration.md) | **Русский**

Все три бинарника намеренно принимают те же флаги, значения по умолчанию и формат конфигурации, что и GoVPN 5.7. Эта страница — авторитетный список для сборки на Rust.

## Флаги `rustvpn-server`

| Флаг | Значение | По умолчанию |
|---|---|---|
| `-bind ADDR` | `host:port` для прослушивания. UDP и TCP используют этот адрес. | `[::]:1194` |
| `-conf PATH` | YAML-файл конфигурации peer'ов. | `peers.yaml` |
| `-proto udp\|tcp\|all` | Транспорт(ы) для обслуживания. | `udp` |
| `-stats ADDR` | Запустить HTTP-эндпоинт статистики в формате JSON на `host:port`. | отключено |
| `-proxy ADDR` | Запустить простой HTTP CONNECT-прокси на `host:port`. | отключено |
| `-egd PATH` | Читать случайные данные из unix-сокета EGD вместо системного RNG. | системный RNG |
| `-warranty` | Вывести уведомление о гарантии по лицензии и завершить работу. | — |

```bash
sudo rustvpn-server -proto all -bind 0.0.0.0:1194 \
    -conf /etc/rustvpn/peers.yaml -stats 127.0.0.1:1294
```

## Флаги `rustvpn-client`

| Флаг | Значение | По умолчанию |
|---|---|---|
| `-remote ADDR` | Сервер `host:port` для подключения. **Обязателен.** | — |
| `-proto udp\|tcp` | Используемый транспорт. `-proxy` принудительно включает `tcp`. | `udp` |
| `-iface NAME` | Имя TAP-интерфейса. | `tap0` |
| `-verifier STR` | Верификатор клиента в короткой форме. **Обязателен.** | — |
| `-key PATH` | Файл парольной фразы; если не задан, запрос в терминале. | запрос |
| `-up PATH` | Скрипт, запускаемый после установления сессии. | — |
| `-down PATH` | Скрипт, запускаемый при отключении/завершении работы. | — |
| `-stats ADDR` | HTTP-эндпоинт статистики в формате JSON. | отключено |
| `-proxy ADDR` | HTTP CONNECT-прокси `host:port`. | напрямую |
| `-proxy-auth USER:PASS` | Учётные данные HTTP Basic для прокси. | — |
| `-mtu N` | Максимальный размер кадра TAP. | `1515` |
| `-timeout N` | Тайм-аут жизнеспособности peer'а в секундах. | `60` |
| `-timesync N` | Временное окно метки времени рукопожатия в секундах (0 = выключено). | `0` |
| `-noise` | Дополнять исходящие пакеты до MTU. | выключено |
| `-encless` | Режим без шифрования (подразумевает noise, только TCP). | выключено |
| `-cpr KIB` | Постоянный темп пакетов в KiB/s. | `0` |
| `-egd PATH` | Сокет EGD для случайных данных. | системный RNG |
| `-warranty` | Вывести уведомление о гарантии и завершить работу. | — |

Проверки, выполняемые при запуске:

- `mtu` должен быть в диапазоне `68..=9015`; режимы noise/encless требуют `mtu >= 120`.
- `-encless` требует `-proto tcp` (или `-proxy`, который принудительно включает TCP).
- Неизвестное значение `-proto` отклоняется.

## Флаги `rustvpn-verifier`

| Флаг | Значение | По умолчанию |
|---|---|---|
| `-key PATH` | Файл парольной фразы; если не задан, запрос. | запрос |
| `-verifier STR` | Проверить парольную фразу по верификатору в длинной форме. | — |
| `-m N` | Стоимость памяти Argon2d (KiB). | `4096` |
| `-t N` | Число итераций Argon2d. | `128` |
| `-p N` | Степень параллелизма Argon2d. | `1` |
| `-egd PATH` | Сокет EGD. | системный RNG |
| `-warranty` | Вывести уведомление о гарантии и завершить работу. | — |

Без `-verifier` инструмент печатает длинную форму и короткую форму (в таком порядке) из одной общей идентичности. С `-verifier` он печатает `true` или `false`.

## `peers.yaml`

Один ключ верхнего уровня на каждого peer'а. Неизвестные поля игнорируются, как и в поведении YAML в Go.

```yaml
alice:
  iface: tap0           # TAP device name; may be empty if up prints it
  mtu: 1515             # max TAP frame size (default 1515, clamped 68..9015)
  up: /etc/rustvpn/up.sh
  down: /etc/rustvpn/down.sh
  timeout: 60           # seconds; <= 0 means 60
  timesync: 0           # handshake timestamp window; 0 = off
  noise: false          # pad every outgoing frame to mtu
  cpr: 0                # constant packet rate, KiB/s; 0 = off
  encless: false        # encryptionless mode (forces noise)
  verifier: $argon2d$m=4096,t=128,p=1$...$...   # LONG form required
```

Правила, применяемые при загрузке файла:

- Должен быть пригоден хотя бы один из `iface` или `up`. Если `iface` пуст, именем интерфейса становится первая строка stdout скрипта up.
- `verifier` должен декодироваться и содержать открытый ключ. Короткая форма отклоняется с ошибкой `server verifier has no public key`.
- `mtu: 0` означает 1515. Значения ограничиваются диапазоном `[68, 9015]`; записи noise/encless поднимаются минимум до 120.
- `encless: true` принудительно включает `noise: true` (заполнение является частью кодирования).
- `timeout <= 0` означает 60 секунд.
- Файл перечитывается каждые **60 секунд**. Неудачный разбор сохраняет последнюю корректную конфигурацию и печатает ошибку.

Каждый peer получает на сервере собственное TAP-устройство. Два peer'а не должны использовать один и тот же `iface`, если они активны одновременно.

## Скрипты (`up` / `down`)

Оба скрипта получают:

| Переменная | Значение |
|---|---|
| `GOVPN_IFACE` | Настроенное имя интерфейса (на сервере может быть пустым). |
| `GOVPN_REMOTE` | Удалённый адрес peer'а. |

Порядок на сервере: **скрипт up → открытие TAP → рукопожатие**. Поскольку демон открывает TAP сам, `up` должен создать постоянное устройство:

```sh
#!/bin/sh
set -eu
IFACE="${GOVPN_IFACE:-tap0}"
ip tuntap add dev "$IFACE" mode tap 2>/dev/null || true
ip link set dev "$IFACE" mtu 1540 up
ip addr replace 10.88.0.1/24 dev "$IFACE"
```

Порядок на клиенте: **открытие TAP → рукопожатие → скрипт up**. `-iface` клиента имеет реальное значение (`tap0` по умолчанию), поэтому его скрипт up обычно настраивает уже существующее устройство:

```sh
#!/bin/sh
set -eu
IFACE="${GOVPN_IFACE:-tap0}"
ip link set dev "$IFACE" mtu 1540 up
ip addr replace 10.88.0.2/24 dev "$IFACE"
ip route replace 10.88.0.0/24 dev "$IFACE"
```

Скрипт `down` запускается при отключении или завершении работы. Делайте оба скрипта идемпотентными (`|| true`, `replace` вместо `add`); клиент переподключается после сбоев.

<a id="mtu"></a>
## MTU

`mtu` — максимальный размер кадра, который демон ожидает от TAP-устройства. Кадры, превышающие эффективный предел полезной нагрузки данного режима, отклоняются и логируются; они никогда не усекаются молча.

| Режим | Эффективный предел полезной нагрузки |
|---|---|
| classic | `MTU - 1` |
| noise | `MTU - 25` (16 tag + 8 nonce + 1 pad) |
| encless | `MTU - 9` (8 nonce + 1 pad) |

При значении по умолчанию `mtu: 1515` это 1514 / 1490 / 1506 байт. Если нужно передать полный IP-пакет размером 1500 байт (Ethernet-кадр 1514 байт) через туннель noise или encless, увеличьте настроенный MTU как минимум до 1540 (noise) или 1524 (encless) и соответствующим образом задайте MTU TAP-интерфейса в скрипте up. Внутренний MTU peer'а не должен превышать эффективную полезную нагрузку.

## Тайм-аут и heartbeat

Поскольку UDP не имеет состояния, peer считается мёртвым после `timeout` секунд без пакетов. Обе стороны должны использовать одно и то же значение (по умолчанию 60). Если в течение четверти тайм-аута ничего не отправлено, испускается heartbeat-пакет, чтобы сессия оставалась живой, даже когда TAP простаивает — это расходует немного трафика.

Сервер периодически очищает устаревших peer'ов и заброшенные состояния рукопожатий (примерно каждые 10 секунд; незавершённые рукопожатия старше 60 секунд отбрасываются). TCP-сессии используют тот же тайм-аут: молча мёртвый TCP-peer обнаруживается по истечении тайм-аута, а не ожидается бесконечно.

## CPR (постоянный темп пакетов)

`cpr: KIB` (или `-cpr`) испускает фиктивный трафик примерно со скоростью `KIB` KiB/s. Цикл пакетов вычисляется из размера на проводе (включая расширение encless) и управляет как отправкой фиктивного трафика, так и интервалом heartbeat. CPR скрывает моменты отправки реальной полезной нагрузки, но требует много трафика и CPU. Используйте его вместе с noise.

## Timesync

`timesync: N` (или `-timesync`) требует, чтобы пакеты рукопожатия были помечены текущей меткой времени, округлённой до `N` секунд. Это защищает от активного DPI, который повторно воспроизводит перехваченный первый пакет рукопожатия, чтобы подтвердить существование данной идентичности и то, что сервер — это GoVPN. Часы на обеих сторонах должны быть разумно синхронизированы. `0` отключает эту функцию.

## Noise

`noise: true` (или `-noise`) дополняет каждый исходящий кадр до MTU. Это скрывает длины пакетов, но может значительно увеличить трафик. Включайте его на обеих сторонах для нужного эффекта. Стоимость полезной нагрузки см. в разделе [MTU](#mtu).

<a id="encless"></a>
## Encless

`encless: true` (или `-encless`) заменяет потоковое шифрование на AONT + Chaffing-and-Winnowing, что сохраняет конфиденциальность, используя только примитивы аутентификации (без функции шифрования). Режим принудительно включает noise и добавляет **4128 байт** к каждому пакету, поэтому он дорог. Клиент поддерживает его только по TCP, как и Go: `-encless` с протоколом UDP по умолчанию отклоняется. См. [Протокол → Encless](protocol.md#encless).

## Эндпоинт статистики

`-stats host:port` запускает минимальный TCP-листенер. Он принимает соединение, игнорирует запрос и возвращает ответ `HTTP/1.0 200 OK` с JSON-массивом объектов peer'ов:

```bash
curl http://127.0.0.1:1294/ | jq .
```

```json
[
  {
    "Addr": "203.0.113.10:52341",
    "Id": "q83v...==",
    "BytesIn": 1392774,
    "BytesOut": 17228877,
    "BytesPayloadIn": 1389000,
    "BytesPayloadOut": 17220000,
    "FramesIn": 12412,
    "FramesOut": 16588,
    "FramesUnauth": 0,
    "FramesDup": 0,
    "HeartbeatRecv": 2,
    "HeartbeatSent": 1,
    "NoiseEnable": false,
    "CPR": 0,

```

`Id` — это кодировка идентичности peer'а в base64 (без заполнения). Все имена полей совпадают с реализацией на Go.

## Прокси

Обе роли могут использовать HTTP CONNECT.

- **Сервер `-proxy host:port`**: принимает любой HTTP-запрос, отвечает `HTTP/1.0 200 OK` и переключается на конечный автомат необработанной TCP-сессии. Он не аутентифицирует клиента прокси.
- **Клиент `-proxy host:port`**: подключается к прокси и отправляет `CONNECT remote:port`. `-proxy-auth user:password` добавляет авторизацию HTTP Basic. Транспорт становится TCP.

Можно использовать любой внешний HTTP-прокси, если он поддерживает CONNECT.

## EGD

`-egd PATH` (во всех бинарниках) читает случайные данные из unix-сокета EGD (entropy gathering daemon — демон сбора энтропии). Используйте его в системах, где `/dev/urandom` не заслуживает доверия. Если параметр не задан, используется системный CSPRNG.

Далее: [Протокол](protocol.md).
