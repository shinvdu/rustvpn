# Руководство RustVPN — обзор

[English](../en/index.md) | [中文](../zh/index.md) | **Русский**

RustVPN — совместимая по проводному формату (wire-compatible) реализация GoVPN 5.7 на Rust. Это руководство описывает, как собрать, настроить, развернуть и понять устройство проекта. Оно адаптировано из оригинального руководства GoVPN: каждая команда, флаг и значение по умолчанию сверены с кодом на Rust.

## Что это такое

RustVPN — небольшой демон виртуальной частной сети, который соединяет TAP-интерфейсы через шифрованный и аутентифицированный туннель. Это не новый протокол: клиент на Rust может работать с сервером на Go, клиент на Go — с сервером на Rust, и любой из бинарников можно заменить с одной стороны, не трогая другую.

Цели дизайна, унаследованные от GoVPN:

- **Проверяемость** — компактная кодовая база и стандартные, хорошо изученные криптографические примитивы.
- **Безопасность** — согласование ключей с аутентификацией по парольной фразе, аутентифицированный транспорт, perfect forward secrecy (совершенная прямая секретность), защита от повторного воспроизведения.
- **Устойчивость к цензуре** — сообщения рукопожатия и транспорта выглядят как случайный шум; необязательное заполнение скрывает их длину и тайминг.
- **Операционная простота** — демон только пересылает пакеты. Адреса, маршруты, MTU и NAT настраивает администратор — точно так же, как для Ethernet-кабеля.

## Краткий обзор возможностей

- Рукопожатие PAKE DH A-EKE с взаимной аутентификацией с нулевым разглашением (zero-knowledge).
- Верификаторы (verifier) на основе Argon2d + Ed25519, устойчивые к офлайн-атакам по словарю.
- Транспорт Salsa20 + Poly1305 с запасом стойкости 128 бит.
- Необязательный режим без шифрования (encless): AONT + Chaffing-and-Winnowing.
- Шумовое заполнение (noise) и необязательный постоянный темп пакетов (CPR).
- Необязательные временные окна для защиты рукопожатия от повторного воспроизведения.
- Встроенные повторное рукопожатие (rehandshake), heartbeat, тайм-аут и статистика в формате JSON.
- Встроенное ограничение частоты рукопожатий (5/с на источник, 200/с глобально).
- Транспорты UDP и TCP, а также HTTP CONNECT-прокси с обеих сторон.
- IPv4 и IPv6.
- Поддержка энтропийного демона EGD для систем со слабым `/dev/urandom`.

## Терминология

| Термин | Значение |
|---|---|
| **Peer** | Именованная запись клиента в серверном `peers.yaml`; по одному TAP-устройству на каждый peer. |
| **Идентичность (identity)** | 128-битный несекретный идентификатор клиента. Используется как ключ XTEA для `IDtag` и как соль Argon2. |
| **Парольная фраза (passphrase)** | Секрет, который запоминает человек и вводит на клиенте. |
| **Верификатор (verifier)** | Токен, производный от Argon2d. Сервер хранит длинную форму (с открытым ключом Ed25519); клиент использует короткую форму. |
| **Рукопожатие (handshake)** | Четырёхсообщённый обмен PAKE, устанавливающий ключ сессии. |
| **Транспорт (transport)** | Аутентифицированный, шифрованный (или кодированный) формат пакетов, используемый после рукопожатия. |
| **Noise** | Дополнение каждого исходящего пакета до настроенного MTU. |
| **Encless** | Режим без шифрования: AONT + Chaffing-and-Winnowing вместо потокового шифрования. |
| **CPR** | Постоянный темп пакетов (constant packet rate): испускать фиктивный трафик с заданной скоростью KiB/s. |
| **MTU** | Настроенный максимальный размер кадра TAP. В режимах noise/encless полезная нагрузка меньше. |

## Статус и ограничения

Реализовано и проверено дифференциальным тестированием: все криптографические примитивы, полное рукопожатие, классический кодек, а также кодек для режимов noise и encless, TAP, конфигурация YAML и горячая перезагрузка (hot reload), скрипты, статистика, прокси, пакетная обработка UDP, TAP на io_uring и Salsa20 с AVX2. Совместимость с бинарниками Go проверена для UDP, TCP, прокси, noise и encless в обоих направлениях.

Известные ограничения:

- Проверена работа только на Linux. FreeBSD и macOS могут работать через крейт `tun`, но не тестировались; задайте `GOVPN_IO_URING=0`, чтобы принудительно использовать TAP-бэкенд на epoll.
- Эффективный MTU не корректируется автоматически. В режимах noise/encless скрипт up должен увеличивать MTU интерфейса (или следует принять меньшую полезную нагрузку).
- Клиент поддерживает режим без шифрования только по TCP — так же, как Go.
